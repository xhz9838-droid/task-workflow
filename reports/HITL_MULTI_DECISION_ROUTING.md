# HITL 多待决策路由规则（2026-11-24）

## 1. 目标

同一钉钉聊天可能同时存在多个待决策任务。裸回复 `A/B/C` 只能在**唯一候选**时生效；
多个候选必须使用 `DEC-ID + 选项`，不允许按最新/数据库顺序猜测。

## 2. 候选定义

对一条来自聊天 `chat_session_key` 的回复：

```text
候选 = 本聊天已绑定（cc_session_key == chat_session_key）的待决决策
     + 未绑定的待决决策（通知时间早于消息；12h 内；未被提醒时间干扰）
```

- 已绑定到其他聊天的决策**不进入候选**；
- 超过 12h 的未绑定决策不自动认领（仍需显式 DEC-ID）；
- 已决/已完成/超时决策不进入候选。

## 3. 路由规则

| 场景 | 行为 |
|---|---|
| 显式 `DEC-ID + 选项` | 精确查找；校验存在、可回复、身份、聊天绑定、选项；通过后接受 |
| 显式 DEC-ID 不存在 | 提示该 ID 不存在，不展示其他决策 |
| 显式 DEC-ID 绑定其他聊天 | 拒绝：“决策绑定到其他会话” |
| 裸选项，候选唯一 | 接受；若未绑定，在身份/选项校验通过后绑定到当前聊天 |
| 裸选项，候选 >1 | 不猜测；返回候选 DEC-ID 列表，要求 `DEC-ID 选项` |
| 裸选项，候选 0 但仍有其他待决 | 提示当前聊天无匹配待决，不展示无关决策 |
| 无待决，回复已决决策 | 作为重复回复提示（不恢复 Agent） |
| 非法选项 | 拒绝并提示可选选项；不恢复 |
| 身份不符 | 拒绝；不绑定、不恢复 |
| 重复消息（同 decision+msg_id） | 唯一约束 + 原子状态守卫，不重复恢复 |

## 4. 解析顺序（实现）

`ReplyHandler.handle`：

1. 解析原始文本（可选 DEC-ID）；
2. `_resolve_decision`：显式 ID 精确查找；否则按候选唯一性；
3. 校验聊天绑定（显式/已绑定均不得跨聊天）；
4. 用该决策的选项重新解析 choice/comment；
5. 身份白名单；
6. 选项合法性；
7. 决策状态可回复；
8. **有效回复才绑定聊天**；
9. `record_reply`（`(decision_id,msg_id)` 唯一）；
10. 条件状态转移（原子守卫）；
11. `SessionResumer.resume` 一次；
12. 发送一次回执。

## 5. 并发与幂等

- `decision_replies(decision_id,msg_id)` 唯一索引：同一决策同一消息只落一次。
- `human_decisions.status` 条件更新（允许来源状态集合）：同一决策只接受一次有效回复。
- 两个消费者（daemon + MCP 轮询）同时看到同一消息时，一个接受，另一个得到 duplicate。
- 不同决策不会因同一消息同时更新，因为候选唯一性由数据库状态决定；
  多候选时直接拒绝，不分发。
- 失败提示只包含本次候选/显式 ID，不包含无关的已决决策。

## 6. 自动化覆盖

`test_reply_binding.py`：

- 单未绑定唯一 → 接受并绑定；
- 已决 RESUMED 不抢新待决（样本 A）；
- 多个新鲜未绑定 → 要求 DEC-ID，提示候选；
- 提醒不改变匹配优先级；
- 超龄未绑定不自动认领；
- 显式 DEC-ID 跨聊天拒绝；
- 显式 DEC-ID + 自定义意见；
- 迟到回复、重复回复、daemon 锁。
